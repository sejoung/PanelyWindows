Panely for Windows 1.1.2 makes reading lighter and fixes problems found in a full review of the app. ZIP files with Korean, Japanese or Chinese file names in older encodings now open with the right names and no missing pages. One damaged archive inside a book no longer stops the rest of it from opening. Exports no longer come out partly untranslated while saying they finished.

**English** · [한국어](#한국어)

## Download

| File | For |
|---|---|
| `Panely-1.1.2-win-x64.zip` | Most Windows PCs (Intel and AMD) |
| `Panely-1.1.2-win-arm64.zip` | Windows on ARM. **Not run on an ARM device yet**, and translation runs on the CPU only. Please report what you see |

Extract the ZIP to a folder and run `Panely.exe`. No installer, administrator rights or .NET install are needed. Checksums are in `SHA256SUMS.txt`.

**Updating from 1.1.x**: close Panely and replace the folder's contents with this ZIP. Your library, reading positions, translations, edits and language packs are kept. You don't need to download anything again. There are two exceptions, both small:

- **ZIP files whose names used to look garbled** now count as having different pages. Translations and edits for those books don't carry over, so they need translating again. If pages that were missing now appear, saved positions and bookmarks in that book can point to a different page.
- **Pages already translated keep their old balloon areas.** To get the fix for numbers next to text (see below), use **Translate This Page Again**.

**Updating from 1.0.x**: see the [1.1.0 notes](https://github.com/sejoung/PanelyWindows/releases/tag/v1.1.0). The translation model changed in 1.1, so books translated with 1.0.x need translating again.

The app isn't code-signed, so SmartScreen may say "Windows protected your PC" on first launch: choose **More info › Run anyway**.

## Reading uses less

These changes came from reading the code, and **their effect on speed and memory hasn't been measured**. They were checked for correct behavior, not for how much they help.

- Turning a page no longer rebuilds the library sidebar or decodes bookmark thumbnails again. A hidden sidebar catches up when you open it.
- The image memory limit now holds. Before, a book of very large pages could go over it. Pages far from the one you're reading are dropped first, and the pages on screen and next to them stay, so it can still go over for a moment.
- Switching books, cleaning the extraction cache and starting the app do less disk work on the main thread, so the window stays responsive.
- Long vertical books lay out less often while their page sizes load, and the thumbnail list loads what's on screen first.
- **Translation models leave memory after 10 minutes without translating**, freeing several GB of RAM and GPU memory. The next translation loads them again, which takes about 20 seconds on a GPU.

## Fixed

**Opening books**

- **ZIP file names in older encodings.** Names saved in Korean (CP949), Japanese (Shift-JIS) or Chinese encodings showed as `��`, and pages whose names became identical were silently left out. Names now show correctly and no page is lost. Panely guesses the encoding for each archive, so a short name can still come out wrong, but the page stays.
- **A damaged archive inside a book.** If the first archive in a ZIP was damaged, the book failed with "Folder is empty or has no supported content" even when the others were fine. If one in the middle was damaged, **Next Volume** stayed on the first volume. Damaged archives are now left out of the volume list.
- **Volumes that no longer exist.** Moving to a volume that's gone now shows an error instead of quietly reopening the first volume.
- **Books close to the size limit** failed while being unpacked, even though they fit once unpacked.
- **Harmful files.** A crafted HEIF image could keep one CPU core busy and stall page loading. An archive could claim a huge page size and make Panely allocate that much memory; a page over 1 GB now shows the safety limit message. A nested ZIP with a damaged file list now leaves the rest of the book readable.
- **Damaged RAR files** stayed locked after a failed open, which could make the whole book fail.

**Your saved data**

- **A locked save file no longer costs you your history.** If another program held `state.json` when Panely started, Panely treated the file as damaged, started from defaults and could overwrite it. It now tries again, and if the file is still locked, it runs without saving and tells you so.
- **Hand-edited save files** with empty entries no longer stop Panely from starting.
- **A failed disk read no longer deletes** extraction cache entries or finished translations.

**Translating and exporting**

- **Exports with missing translations.** **Translate Them First** could finish with untranslated pages while a translation in another layout or for a single page was running. It now checks the results and finishes the work, or says it couldn't.
- **Export As They Are** said nothing was translated for fully translated books that weren't open, after restarting Panely.
- **Exports keep balloons you added** on pages with no translation.
- **Translating again during a translation.** In vertical layout, **Translate This Page Again** or **Translate This Book Again…** during a running translation failed with "Object reference not set". Changing the source language during a translation also works now.
- **Pause** could leave a job stuck on "Preparing" with no way to resume it.
- **Text-heavy pages.** A group of long balloons could fail with "Prompt too long", and trying again failed the same way. Panely now splits the group, and only a balloon too long on its own fails.
- **AI chat replies going to the wrong balloon.** Hiding a balloon after saving the file shifted the numbering, so a reply could land on the wrong balloon. Replies now match the file you saved. If a balloon changed since then, Panely doesn't apply the reply and asks you to save the file again.
- **Added balloons getting the wrong translation.** Removing an added balloon while another was still translating put the result on the wrong one.
- **Damaged translation files** counted as finished pages, so those pages stayed untranslated. Panely now translates them again.
- **Numbers next to text.** "Volume 01" could lose its number, leaving part of the original visible next to the translation.
- **Rare freezes and crashes:** a language pack download starting at the wrong moment could freeze the app, quitting while adding a balloon could crash it, and a download started right after launch could lose its files.

**The app window**

- **Opening an image** that was canceled or failed could move the book you were reading to another page and save that position.
- **Starting Panely again** with no file now brings the running window to the front, restoring it if minimized. Before, nothing visible happened.
- **Two copies no longer run at once.** If Panely was slow to start and you opened a file during that time, a second copy could start and overwrite the first one's saved data. The file now waits and opens in the first copy. If that copy doesn't respond, the second launch tells you and exits.
- **File tree.** A slow folder could overwrite the tree after you switched to another folder. With a drive or network share root as the library, opening a book changed the library folder.
- **The library overlay** could close while a right-click menu in it was open.
- **Closing the window again** while Panely was shutting down could cut cleanup short.
- **Installing file associations** no longer takes over `.cbz`/`.cbr` from a reader registered for all users on the PC.

## For developers

- `install-local` refuses a non-empty folder without `install-info.json`. Before, `-InstallDir D:\Apps` deleted everything else in that folder.
- `uninstall-local` also removes file associations and the folder menu, but only when they point to the install being removed.
- `verify.cmd` passes on Windows with 610 unit and contract tests plus 5 real-app smoke tests.
- Decisions are recorded in [ADR 0009](https://github.com/sejoung/PanelyWindows/blob/main/docs/adr/0009-reader-performance.md) and [ADR 0010](https://github.com/sejoung/PanelyWindows/blob/main/docs/adr/0010-robust-opening-and-state.md).

## Known limitations

- **Some fixes were checked by automated tests only, not by hand in the app**: the AI chat reply check, translating added balloons, splitting long groups with the real model, quitting while adding a balloon, the overlay staying open during a menu, switching roots on a slow share, a drive root as the library, the HKLM file association check, and a slow cold start. Please report anything odd.
- After restarting Panely, save the AI chat file again before pasting a reply. Saved files are remembered only while the app is running.
- RAR file names weren't changed in this release.
- Translation is experimental and makes mistakes, especially when text recognition misreads the original. Quality hasn't been checked against a golden set.
- **Without a usable GPU, translation is several times slower.** Windows on ARM always translates on the CPU.
- In the AI chat window, the prompt shows a balloon count of 0 until you click **Save as Text File…**. Save the file first, then copy the prompt.
- Not tested yet: Windows on ARM, 125/150% and mixed-DPI setups, high-contrast mode.
- Translation jobs in progress are lost when you quit (finished pages are kept).

## 한국어

Panely Windows 1.1.2는 읽을 때의 부담을 줄이고, 앱 전체를 검토하며 찾은 문제를 고칩니다. 예전 인코딩의 한국어·일본어·중국어 파일 이름이 든 ZIP도 이제 이름이 제대로 보이고 빠지는 페이지가 없습니다. 책 안의 압축 파일 하나가 손상돼도 나머지는 열립니다. 일부만 번역된 채 완료로 끝나던 내보내기도 고쳤습니다.

### 내려받기

| 파일 | 대상 |
|---|---|
| `Panely-1.1.2-win-x64.zip` | 대부분의 Windows PC(Intel·AMD) |
| `Panely-1.1.2-win-arm64.zip` | ARM 기반 Windows. **실제 ARM 기기에서는 아직 실행해 보지 않았고**, 번역은 CPU로만 돕니다. 실행 결과를 알려 주세요 |

ZIP을 폴더에 풀고 `Panely.exe`를 실행합니다. 설치 프로그램, 관리자 권한, .NET 설치가 필요 없습니다. 체크섬은 `SHA256SUMS.txt`에 있습니다.

**1.1.x에서 업데이트**: Panely를 닫고 폴더 내용을 이 ZIP으로 바꿉니다. 라이브러리, 읽던 위치, 번역 결과, 고친 내용, 언어팩은 그대로 남습니다. 다시 받을 것은 없습니다. 예외는 작은 것 두 가지입니다.

- **이름이 깨져 보이던 ZIP**은 페이지가 달라진 것으로 처리됩니다. 그 책의 번역 결과와 고친 내용은 이어지지 않아 다시 번역해야 합니다. 빠져 있던 페이지가 나타나면 저장된 위치와 북마크가 다른 페이지를 가리킬 수 있습니다.
- **이미 번역한 페이지는 예전 말풍선 영역을 그대로 씁니다.** 글자 옆 숫자 수정(아래 참고)을 적용하려면 **이 페이지 다시 번역**을 쓰세요.

**1.0.x에서 업데이트**: [1.1.0 릴리스 노트](https://github.com/sejoung/PanelyWindows/releases/tag/v1.1.0)를 보세요. 1.1에서 번역 모델이 바뀌어 1.0.x에서 번역한 책은 다시 번역해야 합니다.

코드 서명이 없어 처음 실행할 때 SmartScreen이 "Windows의 PC 보호" 창을 띄울 수 있습니다. **추가 정보 › 실행**을 누르세요.

### 읽을 때의 부담 줄이기

코드를 읽어 찾아 고친 것이고, **속도와 메모리 효과는 측정하지 않았습니다.** 올바르게 동작하는지는 확인했지만 얼마나 나아졌는지는 확인하지 않았습니다.

- 페이지를 넘길 때 라이브러리 사이드바를 다시 만들거나 북마크 썸네일을 다시 디코드하지 않습니다. 숨겨진 사이드바는 열 때 한 번에 맞춥니다.
- 이미지 메모리 상한을 실제로 지킵니다. 전에는 아주 큰 페이지로 된 책에서 상한을 넘을 수 있었습니다. 읽는 곳에서 먼 페이지부터 버리고, 화면의 페이지와 그 옆 페이지는 남기므로 잠깐 넘을 수는 있습니다.
- 책 전환, 압축 해제 캐시 정리, 앱 시작 때 주 스레드에서 하는 디스크 작업을 줄여 창이 덜 멈춥니다.
- 긴 세로 책은 페이지 크기를 읽는 동안 배치를 덜 자주 계산하고, 썸네일은 화면에 보이는 것부터 읽습니다.
- **번역을 10분 동안 하지 않으면 번역 모델을 메모리에서 내립니다.** RAM과 GPU 메모리 수 GB가 비워집니다. 다음 번역 때 다시 올리며, GPU에서는 약 20초 걸립니다.

### 고친 것

**책 열기**

- **예전 인코딩의 ZIP 파일 이름.** 한국어(CP949), 일본어(Shift-JIS), 중국어 인코딩으로 저장된 이름이 `��`로 보였고, 이름이 같아진 페이지는 아무 안내 없이 빠졌습니다. 이제 이름이 제대로 보이고 페이지가 빠지지 않습니다. 인코딩은 압축 파일마다 추측하므로 짧은 이름은 여전히 틀릴 수 있지만 페이지는 남습니다.
- **책 안의 손상된 압축 파일.** ZIP 안의 첫 압축 파일이 손상되면 나머지가 멀쩡해도 "폴더가 비어 있거나 지원하는 파일이 없습니다" 오류로 열리지 않았습니다. 중간 파일이 손상되면 **다음 권**이 첫 권에 머물렀습니다. 이제 손상된 파일은 권 목록에서 뺍니다.
- **없어진 권.** 없어진 권으로 이동하면 조용히 첫 권을 다시 여는 대신 오류를 보여 줍니다.
- **크기 한도에 가까운 책**이 풀어 놓으면 한도 안에 드는데도 푸는 중에 실패했습니다.
- **악의적인 파일.** 조작된 HEIF 이미지가 CPU 코어 하나를 계속 쓰며 페이지 읽기를 멈출 수 있었습니다. 압축 파일이 페이지 크기를 크게 속이면 그만큼 메모리를 잡았는데, 이제 1GB가 넘는 페이지는 안전 한도 안내를 보여 줍니다. 파일 목록이 손상된 중첩 ZIP이 있어도 책의 나머지는 읽을 수 있습니다.
- **손상된 RAR 파일**이 열기에 실패한 뒤에도 잠겨 있어 책 전체가 실패할 수 있었습니다.

**저장된 데이터**

- **저장 파일이 잠겨 있어도 기록을 잃지 않습니다.** Panely를 시작할 때 다른 프로그램이 `state.json`을 잡고 있으면 손상된 파일로 보고 기본값으로 시작해 파일을 덮어쓸 수 있었습니다. 이제 다시 시도하고, 그래도 잠겨 있으면 저장하지 않고 동작하며 그 사실을 알려 줍니다.
- **직접 고친 저장 파일**에 빈 항목이 있어도 시작이 막히지 않습니다.
- **디스크 읽기 실패로** 압축 해제 캐시나 완료한 번역을 지우지 않습니다.

**번역과 내보내기**

- **번역이 빠진 내보내기.** 다른 보기 방식이나 한 페이지만 번역하는 작업이 돌고 있으면 **먼저 번역하기**가 번역 안 된 페이지를 남긴 채 끝날 수 있었습니다. 이제 결과를 확인해 남은 작업을 마치거나, 마치지 못했다고 알려 줍니다.
- **그대로 내보내기**가 Panely를 다시 시작한 뒤 열려 있지 않은 책에서는 번역이 끝난 책도 번역된 것이 없다고 했습니다.
- **번역이 없는 페이지에서도** 직접 추가한 말풍선을 내보냅니다.
- **번역 중에 다시 번역하기.** 세로 보기에서 번역 중에 **이 페이지 다시 번역**이나 **이 책 다시 번역…**을 고르면 "Object reference not set" 오류로 실패했습니다. 번역 중에 원문 언어를 바꾸는 것도 이제 됩니다.
- **일시정지**한 작업이 "준비 중"에 멈춰 재개할 수 없는 경우가 있었습니다.
- **글자가 많은 페이지.** 긴 말풍선 묶음이 "Prompt too long"으로 실패했고 다시 해도 같았습니다. 이제 묶음을 나눠 번역하며, 혼자서도 너무 긴 말풍선만 실패합니다.
- **AI 채팅 답이 다른 말풍선에 들어가는 문제.** 파일을 저장한 뒤 말풍선을 숨기면 번호가 밀려 답이 다른 말풍선에 들어갈 수 있었습니다. 이제 답은 저장한 파일을 기준으로 맞춥니다. 그 뒤 말풍선이 바뀌었으면 적용하지 않고 파일을 다시 저장하라고 안내합니다.
- **추가한 말풍선의 번역이 뒤바뀌는 문제.** 다른 말풍선을 번역하는 동안 추가한 말풍선을 지우면 결과가 엉뚱한 말풍선에 들어갔습니다.
- **손상된 번역 파일**을 완료된 페이지로 쳐서 그 페이지가 번역되지 않은 채 남았습니다. 이제 다시 번역합니다.
- **글자 옆의 숫자.** "Volume 01"에서 숫자가 빠져 번역 옆에 원문 일부가 보일 수 있었습니다.
- **드물게 일어나던 멈춤과 충돌**: 언어팩 다운로드가 특정 순간에 시작되면 앱이 멈출 수 있었고, 말풍선을 추가하는 중에 종료하면 앱이 죽을 수 있었고, 앱을 켠 직후 시작한 다운로드는 파일을 잃을 수 있었습니다.

**앱 창**

- **이미지 열기**가 취소되거나 실패하면 읽던 책이 다른 페이지로 넘어가고 그 위치가 저장될 수 있었습니다.
- **파일 없이 Panely를 다시 실행**하면 실행 중인 창이 앞으로 옵니다. 최소화되어 있으면 되돌립니다. 전에는 눈에 보이는 변화가 없었습니다.
- **두 개가 동시에 실행되지 않습니다.** Panely가 느리게 시작되는 동안 파일을 열면 두 번째 Panely가 떠서 첫 번째의 저장 데이터를 덮어쓸 수 있었습니다. 이제 파일은 기다렸다가 첫 번째 창에서 열립니다. 첫 번째가 응답하지 않으면 두 번째 실행은 안내하고 끝납니다.
- **파일 트리.** 다른 폴더로 바꾼 뒤 느린 폴더의 결과가 트리를 덮어쓸 수 있었습니다. 드라이브나 네트워크 공유의 루트를 라이브러리로 쓰면 책을 열 때 라이브러리 폴더가 바뀌었습니다.
- **라이브러리 오버레이**가 그 안의 오른쪽 클릭 메뉴가 열려 있는 동안 닫힐 수 있었습니다.
- **종료 중에 창을 다시 닫으면** 정리 작업이 중간에 끊길 수 있었습니다.
- **파일 연결을 등록할 때** 이 PC의 모든 사용자용으로 등록된 다른 앱의 `.cbz`/`.cbr` 연결을 가로채지 않습니다.

### 개발자용

- `install-local`은 `install-info.json`이 없고 비어 있지 않은 폴더를 거부합니다. 전에는 `-InstallDir D:\Apps`로 실행하면 그 폴더의 다른 파일이 모두 지워졌습니다.
- `uninstall-local`은 파일 연결과 폴더 메뉴도 지웁니다. 지우는 설치본을 가리킬 때만 지웁니다.
- Windows에서 `verify.cmd`를 통과했습니다(단위·계약 테스트 610개, 실제 앱 smoke 테스트 5개).
- 결정 기록은 [ADR 0009](https://github.com/sejoung/PanelyWindows/blob/main/docs/adr/0009-reader-performance.md)와 [ADR 0010](https://github.com/sejoung/PanelyWindows/blob/main/docs/adr/0010-robust-opening-and-state.md)에 있습니다.

### 알려진 제약

- **일부 수정은 자동 테스트로만 확인했고 앱에서 직접 눌러 보지 않았습니다**: AI 채팅 답 확인, 추가한 말풍선의 번역, 실제 모델에서 긴 묶음 나누기, 말풍선 추가 중 종료, 메뉴가 열린 동안 오버레이 유지, 느린 공유 폴더에서 루트 바꾸기, 드라이브 루트 라이브러리, HKLM 파일 연결 확인, 느린 콜드 스타트. 이상한 점이 있으면 알려 주세요.
- Panely를 다시 시작했다면 AI 채팅 답을 붙여넣기 전에 파일을 다시 저장하세요. 저장한 파일 정보는 앱이 켜져 있는 동안만 기억합니다.
- 이번 릴리스에서 RAR 파일 이름은 바꾸지 않았습니다.
- 번역은 실험 기능이라 틀릴 때가 있고, 특히 글자 인식이 원문을 잘못 읽으면 번역도 틀립니다. 골든 세트로 품질을 검수하지 않았습니다.
- **쓸 수 있는 GPU가 없으면 번역이 몇 배 느립니다.** ARM 기반 Windows는 항상 CPU로 번역합니다.
- AI 채팅 창의 안내문은 **텍스트 파일로 저장…**을 누르기 전에는 말풍선 수를 0으로 표시합니다. 파일을 먼저 저장한 뒤 안내문을 복사하세요.
- 아직 확인하지 않은 환경: ARM 기반 Windows, 125/150% 및 혼합 DPI, 고대비 모드.
- 진행 중인 번역 작업은 앱을 종료하면 사라집니다(완료한 쪽은 남습니다).
