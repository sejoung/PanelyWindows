# ADR 0010: 전체 검토에서 찾은 결함을 고치며 정한 동작

- 상태: 채택
- 날짜: 2026-11-02
- 보완: [ADR 0005](0005-ai-chat-file-exchange.md) 4번, [ADR 0009](0009-reader-performance.md)
- 관련 코드: `ZipNameDecoder`, `FolderAnalyzer`(`expandedOnly`), `BookOpener.StrictInnerPath`, `ExtractionLimits.CheckEntrySize`, `StateStore.IsReadFailure`, `SingleInstance`, `ModelGate`, `ExportScheduler.TranslateMissingAsync`, `TranslationCache.Contains`, `GemmaTranslator.GenerateLines`, `BalloonGrouper.RowNumbers`
- 테스트: `ZipReaderTests`, `BookOpenerTests`, `StateStoreTests`, `TranslationReviewRegressionTests`, `SingleInstanceTests`, `ShellLogicTests`, `LibrarySidebarTests`, `LocalScriptTests`

## 배경

처음으로 Windows에서 `verify.cmd`를 돌리고 코드 전체를 검토했다. 빌드와 테스트는 통과했지만 테스트가 닿지 않는 경로에 결함이 있었다. 그중 CP949 ZIP 이름 깨짐, 손상된 중첩 아카이브, HEIF 헤더 무한 루프는 실제로 재현했다. 대부분은 버그 수정이지만 아래는 사용자에게 보이는 동작을 정한 것이어서 기록한다.

## 결정

1. **ZIP 이름**: UTF-8 표시가 있는 이름은 그대로 둔다. 표시 없는 비ASCII 이름은 아카이브마다 인코딩 하나를 고른다. 순서는 UTF-8 → 시스템 코드 페이지(CJK일 때) → 949 → 932 → 936 → 950 → 시스템 코드 페이지(단일 바이트일 때)다. 단일 바이트 코드 페이지는 어떤 바이트든 풀어내므로 마지막에 둔다. 어느 것도 맞지 않으면 쪽을 버리지 않고 이름을 구분해 남긴다. 추측이므로 짧은 이름은 잘못 고를 수 있지만, 그래도 쪽은 잃지 않는다.
2. **펼치지 못한 중첩 아카이브는 권이 아니다.** 권 목록과 첫 권 선택에서 뺀다. 권 이동과 트리의 권 선택이 가리킨 권이 없으면 첫 권으로 돌아가지 않고 오류를 보인다.
3. **쪽 하나는 1GiB까지 메모리로 읽는다.** 아카이브가 선언한 크기는 믿을 수 없어 할당 전에 확인한다.
4. **저장 파일을 읽지 못하면(잠김·권한) 손상이 아니다.** 잠깐 다시 시도하고, 그래도 안 되면 읽기 전용으로 동작해 멀쩡한 파일을 덮지 않는다. 격리 사본은 만들지 않는다.
5. **Mutex를 쥔 첫 인스턴스가 있으면 두 번째 인스턴스로 계속하지 않는다.** 파이프 서버는 창을 만들기 전에 열고 요청은 창이 준비될 때까지 쌓는다. 후속 실행은 10초까지 다시 시도하고, 그래도 안 되면 안내하고 끝낸다. 경로 없는 후속 실행은 기존 창을 앞으로 가져온다.
6. **AI 채팅 답은 그 파일을 저장할 때의 snapshot에만 적용한다.** snapshot은 메모리에 보관해 창을 닫았다 열어도 쓰지만 앱을 끄면 사라진다. 바꿀 줄 중 하나라도 저장 때의 말풍선을 가리키지 않으면 답 전체를 거부하고 다시 저장하라고 안내한다. 잘못된 말풍선에 조용히 쓰는 것보다 다시 저장하는 편이 낫다.
7. **내보내기는 작업이 끝났다는 사실만 믿지 않고 캐시를 다시 확인한다.** (책, 대상 언어)당 작업은 하나이고 범위나 쪽 지정이 다를 수 있기 때문이다. 다른 범위로 도는 작업은 끊지 않고 끝나기를 기다린다.
8. **번역 캐시 `Contains`는 끝 두 바이트만 본다.** 온전한 파일은 언제나 `]}`로 끝난다(이 PC의 기존 캐시 298개로 확인). 책 전체에 대해 부르므로 파싱하지 않는다. 내용 손상은 `TryLoad`가 잡고, 입출력 오류로는 파일을 지우지 않는다.
9. **`AnalysisVersion`을 올리지 않는다.** 같은 줄의 숫자 조각을 말풍선에 포함하도록 묶음 규칙을 바꿨으므로("Volume" + "01") 코드 주석대로라면 올려야 한다. 드문 경우를 고치려고 모든 사용자의 번역 캐시를 버리는 비용이 더 크다고 판단했다. 이미 번역한 쪽은 "이 쪽 다시 번역"을 해야 바뀐다.

## 결과

- 이름이 깨져 있던 아카이브는 표시 이름과 `PageId`가 바뀐다. 그 쪽의 번역 캐시·수정은 이어지지 않고, 이름 충돌로 빠졌던 쪽이 나타나면 쪽 번호가 밀려 저장된 위치·북마크가 다른 쪽을 가리킬 수 있다.
- 응답 없는 첫 인스턴스가 있으면 후속 실행은 파일을 열지 못하고 끝난다.
- 앱을 다시 시작하면 AI 채팅 답을 붙여넣기 전에 파일을 다시 저장해야 한다.
- RAR 이름은 이번에 건드리지 않았다(RAR4는 유니코드 이름을 함께 저장한다).
