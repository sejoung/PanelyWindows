# ADR 0005: AI 채팅으로 다듬기는 파일·클립보드로만 주고받는다

- 상태: 채택(첫 구현 때 정한 것을 2026-10-19에 사후 기록)
- 날짜: 2026-10-19
- 관련 코드: `AiChatSheet`, `AiChatExchange`(Domain), `AiChatPrompt`, `TranslationFeature.BuildLanguageMenuItems`·`BuildPageContextMenuItems`, `TranslationPanel.BuildBookSection`
- 테스트: `tests/Panely.Tests/Translation/TranslationVectorTests.cs`(파일 형식·응답 파서 벡터), `TranslationAlgorithmTests.cs`(변경 계산). 응답 인코딩 판별(`AiChatSheet.DecodeReply`)은 테스트가 없다

## 배경

말풍선을 하나씩 기계 번역하면 누가 말하는지, 인물별 말투, 이름 표기를 맞출 수 없다. 책 전체를 읽는 대화형 AI(ChatGPT, Claude, Gemini 등)는 이것을 잘 고친다. 하지만 앱이 AI 서비스 API를 직접 부르면 다음 문제가 생긴다.

- 사용자가 모르는 사이 만화 글이 외부로 나간다. 번역은 PC 안에서만 한다는 원칙(ADR 0004)과 어긋난다.
- API 키 보관, 요금, 서비스별 연동을 앱이 떠안는다.

## 결정

1. 앱은 AI 서비스에 요청하지 않는다. 사용자가 쓰는 채팅을 그대로 쓰고, 앱은 파일을 만들고 받은 답을 적용하는 일만 한다.
2. 흐름은 원본 Panely와 같다.
   1. 범위(책 전체 또는 쪽 구간)를 고르면 담길 말풍선 수를 보여 준다.
   2. 텍스트 파일로 저장한다(UTF-8, 한 줄에 `[id] 원문 → 번역`).
   3. 안내문(프롬프트)을 복사한다. 사용자가 고쳐 쓸 수 있다.
   4. 채팅이 돌려준 파일을 열거나 답을 붙여넣는다. `[id] 번역` 줄만 읽고, 바뀐 말풍선만 적용한다.
3. 적용한 번역은 사용자 수정으로 저장한다. 말풍선마다 기계 번역으로 되돌릴 수 있고, 방금 적용한 답 전체를 한 번에 되돌릴 수도 있다. 이 일괄 되돌리기는 텍스트 입력의 Undo(Ctrl+Z)와 별개다.
   - 적용 결과는 3단계 아래 카드로 보여 준다. 모두 돌아왔으면 ✓ "답을 적용했습니다", 빠진 말풍선이 있으면 ⚠와 빠진 id 목록을 보여 준다. 되돌리기는 카드 안의 "이 답 되돌리기" 링크로 두고, 창의 주 버튼은 "완료"다. 처음에는 결과를 작은 글씨로만 쓰고 그 아래에 "실행 취소" 버튼을 따로 두었다. 그러자 버튼만 눈에 띄어 적용이 끝났는지 알기 어려웠다(2026-10-19 변경).
   - 창은 적용 뒤에도 열어 둔다. 빠진 말풍선만 채팅에 다시 요청해서 이어 붙여넣을 수 있게 하기 위해서다.
4. 응답은 파일을 저장할 때 만든 snapshot에 맞춘다. 범위를 바꾸면 snapshot을 버린다. 파일에 없던 id는 무시하고, 빠진 id는 개수와 함께 알려 준다.
5. 응답 파일은 UTF-8(BOM 허용)과 UTF-16(BOM 있음)만 읽고, 잘못된 UTF-8은 거부한다.
6. 진입점은 세 곳이다. 툴바 언어 메뉴, 페이지 우클릭 메뉴, 번역 패널의 "이 책과 시리즈". 툴바 메뉴에서 빠졌던 것을 2026-10-19에 원본과 같은 자리로 되돌렸다.

## 결과

- 사용자가 채팅에 직접 넘길 때만 글이 PC 밖으로 나간다. 창 아래에 이 사실을 적어 둔다.
- 앱에 API 키나 네트워크 코드가 없다. 대신 저장 → 첨부 → 붙여넣기를 사용자가 직접 한다.
- 채팅이 줄 형식을 지키지 않으면 적용할 수 없다. 안내문에 형식을 적고, 파일을 못 만들면 코드 블록 하나로 답하라고 요청한다.
