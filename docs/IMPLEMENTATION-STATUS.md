# 구현·검수 현황

기준일 2026-10-16. 빌드 Windows 11 Pro 10.0.26200 x64, .NET SDK 10.0.402, 디스플레이 200%. 기능 ID와 "01~09 문서"는 첫 포팅 명세(`docs/windows/`)를 가리키며, 이 명세는 2026-10-19에 저장소에서 지웠다([ADR 0002](adr/0002-retire-porting-spec.md)). 원문은 커밋 `45c0cb1`에서 볼 수 있다.

**상태 요약**: 01 문서의 모든 기능 ID를 코드로 구현했습니다. 자동 테스트 461개가 통과합니다(단위·계약 458개 + 실제 앱 smoke 3개, 2026-10-20 기준). `verify.cmd`가 린트·경고 없는 빌드·테스트·게시본(ReadyToRun) smoke를 한 번에 확인합니다. 커버리지는 Core+Domain 78.9%이고, UI 계층은 smoke로 확인합니다. 리더·라이브러리·번역·내보내기는 실제 앱을 띄워 확인했습니다(UI Automation과 화면 캡처). 아래 "미검증/제약"에 적은 항목은 실제 환경에서 확인하지 못했거나 명세와 다르게 동작하는 부분입니다. 09 문서의 "전체 포팅 완료" 조건 중 깨끗한 PC 검수, 번역 품질 골든 세트, installer는 아직 충족하지 않았습니다.

## 번역 모델 상태

| 모델 | 상태 |
|---|---|
| 말풍선 탐지 `detector.onnx` (Apache-2.0) | revision·sha256 고정. 이 export의 출력은 명세의 Core ML 계약과 다르며(`labels/scores/boxes`, 절대 xyxy, `orig_target_sizes` 입력) manifest `boxFormat: postprocessed-xyxy`로 처리 |
| 일본어 OCR manga-ocr int8 (Apache-2.0) | revision·sha256 고정(comic-translate 등록값과 일치). 세평유(일본어 세로 웹툰)에서 세로 대사 인식 확인 |
| PP-OCRv5 mobile 탐지 + ch/en/korean 인식 (Apache-2.0) | revision·sha256 고정. 영어·한국어 페이지 인식, 언어 감지(ja/en/ko 각 1건) 확인 |

### 처리 장치와 속도(이 PC 실측, 웹툰 12쪽/말풍선 12개, 세션 생성 포함)

| 단계 | GPU (DirectML) | CPU | 기본 |
|---|---|---|---|
| 말풍선 탐지 RT-DETR fp32 | 2.1초 | 5.4초 | GPU |
| manga-ocr int8 | 3.8초 | 0.9초 | CPU |
| PP-OCR mobile 인식 | 1.0~1.6초 | 0.6초 | CPU |
| PP-OCR 줄 탐지(일본어 글자 크기 측정, 세평유 93상자) | 139ms/상자 | 205ms/상자 | GPU |
| M2M100 int8 번역 | 세션 생성 중 네이티브 충돌(0xC0000005) | 1.6초(KV 캐시·배치) | CPU |

분석(탐지+OCR)과 번역은 겹쳐 돌고, 번역기에는 여러 쪽의 풍선이 8개씩 묶여 들어갑니다([ADR 0003](adr/0003-translation-pipeline.md)). 세평유 60쪽은 strip 범위 22.2초, 쪽 범위 29.1초입니다. `PANELY_ORT_DEVICE=cpu`로 GPU를 끌 수 있습니다. GPU는 DirectX 12 GPU면 제조사와 상관없이 DirectML로 쓰고, 실패하면 CPU로 돌아갑니다. 앱에 재배포용 `DirectML.dll` 1.15.4를 함께 넣습니다.

### 빠르게·정확하게 비교(2026-10-20, 1회 측정)

세평유 298쪽(세로 웹툰, 일본어 → 한국어, 세로 스크롤 strip 범위, 말풍선 146개)을 새 데이터 폴더에서 처음부터 번역했습니다. 시간은 앱 실행부터 298쪽이 모두 완료될 때까지이며, 탐지·OCR·번역과 세션 생성을 모두 포함합니다. PC는 Intel Core i7-13700K, RAM 64GB, NVIDIA GeForce RTX 4070 Ti SUPER(탐지는 DirectML, 번역은 CPU)입니다.

| 모드 | 전체 시간 | 첫 번역 표시 | 최대 작업 집합 | 최대 개인 메모리 |
|---|---|---|---|---|
| Fast (int8) | 83.0초 | 10.6초 | 3.5GB | 5.2GB |
| Accurate (fp32) | 90.2초 | 13.6초 | 5.8GB | 7.4GB |

말풍선이 적은 책이라 시간 대부분은 탐지·OCR이 차지하고, 번역 모델 차이는 약 7초입니다. 말풍선이 많은 책에서는 차이가 더 벌어질 수 있습니다. Accurate는 메모리를 약 2.2GB 더 씁니다. 원문 인식 결과는 두 모드가 같았고(146개 모두 동일), 번역은 115개가 달랐습니다. 개발자가 두 결과를 나란히 비교한 평가로는 Accurate가 훨씬 나았습니다. 한 사람의 주관 평가이며 골든 세트로 검수한 결과는 아닙니다.

## 알려진 차이·개선 후보

- 텍스트가 상자를 거의 꽉 채운 내레이션 상자는 표본 고리가 상자 테두리를 지나 "그림 위 글자"로 판정됩니다. 그러면 명세대로 α.92 패치를 그리므로 원문이 희미하게 비칩니다.
- 실행 중인 번역 작업은 앱을 종료하면 사라집니다(명세상 durable queue는 선택). 번역·내보내기 중에 종료하면 먼저 확인합니다([ADR 0007](adr/0007-reader-ui-gaps.md)).
- 깨끗한 Windows PC, 125/150% 및 혼합 DPI, ARM64, 고대비 모드는 확인하지 않았습니다. ARM64는 게시본의 네이티브 DLL(ONNX Runtime, DirectML, Magick.Native, coreclr)이 ARM64인 것만 확인했습니다(2026-10-20).
- 배포는 태그 push 시 GitHub 릴리스로 올라가는 self-contained portable zip(win-x64/win-arm64, `tools/release.ps1` → `.github/workflows/release.yml`)입니다. 서명된 installer/MSIX는 없습니다. 릴리스 노트는 `docs/releases/vX.Y.Z.md`에 씁니다.
